Le problème

Une attaque, quatre étapes d’apparence anodine

Chaque étape semble normale prise isolément : lire un fichier, interroger la base, envoyer une requête web. Ce n’est qu’ensemble qu’elles révèlent une attaque. ShieldTrail les regarde ensemble.

01injection de prompt

Instruction cachée

L’agent ouvre une facture PDF qui contient un texte écrit pour l’IA, pas pour les humains.

02outil hors périmètre

Requête inhabituelle

Il lance une requête dont la tâche n’avait pas besoin : tous les clients avec leurs numéros de carte.

03domaine inconnu

Envoi des données

Il tente d’envoyer cette liste vers un site que personne n’a jamais utilisé.

04bloqué

ShieldTrail bloque

La requête ne quitte jamais l’application. Toute la chaîne est enregistrée avec la raison.

Fonctionnement

Trois idées, rien de plus

Il suit toute la tâche

Ce que l’agent lit, les outils qu’il appelle et les requêtes qu’il envoie sont reliés. Dès qu’une instruction cachée entre, chaque étape suivante est surveillée de près.

Il n’arrête que la mauvaise étape

La requête qui ferait sortir les données ne part jamais. Le reste de l’application continue, et chaque décision dit pourquoi.

Observer d’abord, bloquer ensuite

Commencez en observation : ShieldTrail note ce qu’il bloquerait, sans rien toucher. Activez le blocage, règle par règle, quand vous lui faites confiance.

Ce que vous obtenez

Utile dès le premier jour

Un panneau sur votre application

En développement, un bouclier apparaît dans le coin de chaque page où un agent a agi et montre ce qui s’est passé.

Demander à une personne

Les étapes risquées, comme un remboursement, attendent qu’une personne clique sur « Autoriser ».

Vos clés restent chez vous

Votre clé Stripe ne peut aller que chez Stripe. Envoyée ailleurs, elle est arrêtée.

Pas de facture qui s’emballe

Des limites par tâche : appels, durée, jetons et argent.

Tout arrêter

Un bouton arrête tous les agents pendant un incident.

Un rapport à partager

Un fichier HTML pour votre équipe sécurité, plus export SIEM et OpenTelemetry.

Dans votre code

Quelques lignes dans votre application

Un garde, puis enveloppez ce que l’agent lit, les outils qu’il appelle et le travail qu’il fait.

Guide complet 
// lib/guard.ts — the rules live in shieldtrail.policy.json
import { createGuard } from 'shieldtrail/node';

export const guard = createGuard({
  secrets: [{ name: 'STRIPE_KEY', value: process.env.STRIPE_KEY, domains: ['api.stripe.com'] }],
});

// where your agent runs
const trace = guard.startTrace({ agent: 'support-bot', task: 'Answer ticket #4521', allowedTools: ['tickets.*'] });
await trace.context({ source: attachmentUrl, text: pdfText });   // what the agent reads
const rows = await trace.tool('db.query', args, () => db.query(args));
await trace.run(() => agent.next());   // every fetch inside goes through the rules
// a request to an unknown domain after an injection throws GuardBlockedError: it never leaves

console.log((await trace.chain()).narrative);
