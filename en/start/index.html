Get started

Everything runs locally. No account, no API key, no AI model. Follow the steps in order — each one takes about a minute.

What you need

Node.js 20 or newergita terminal
Check your Node.js version:
$ node -v
1

Run the demo in your terminal

Get the code, then play the same attack twice: without ShieldTrail, then with it.

Get the code
$ git clone https://github.com/SergeMiro/ShieldTrail.git
$ cd ShieldTrail
$ npm install
Without ShieldTrail — the card numbers leak
$ npm run demo -- --mode off
With ShieldTrail — the theft is stopped, the app keeps working
$ npm run demo -- --mode enforce
At the end of the last run you should see:
BLOCKED     5. POST customers to exfil.attacker.dev
            BLOCKED by exfil-after-injection. Request never left the app.
OK          6. Reply to customer

Data that reached the attacker: none

See the panel in a real Next.js app

Build ShieldTrail and start the example

$ npm run dev -w shieldtrail-next-example
Open the page with the attack, then click the shield in the corner

3

Add it to your app

ShieldTrail is not on npm yet, so build it from the folder you cloned and install it from there.

Build, then install into your project
$ npm run build
$ cd ../your-app
$ npm install ../ShieldTrail/packages/shieldtrail
Then create one guard, wrap what your agent does, and add the panel:
// lib/guard.ts — reads shieldtrail.policy.json, starts the dev panel in development
import { createGuard } from 'shieldtrail/node';
export const guard = createGuard({
  secrets: [{ name: 'STRIPE_KEY', value: process.env.STRIPE_KEY, domains: ['api.stripe.com'] }],
});

// where your agent runs
const trace = guard.startTrace({ agent: 'support-bot', task: 'Answer a ticket', allowedTools: ['tickets.*'] });
await trace.context({ source: fileUrl, text: fileText });              // what the agent reads
const rows = await trace.tool('db.query', args, () => db.query(args)); // each tool call
await trace.run(() => agent.next());                                    // every fetch inside is checked
await trace.usage(completion.usage);                                    // tokens, for budgets

// app/layout.tsx — the panel, development only (Next.js: serverExternalPackages: ['shieldtrail'])
{process.env.NODE_ENV === 'development' && <script src="http://127.0.0.1:4320/panel.js" async />}
4

Roll out safely

Start in watch-only mode, read what would have been blocked, then turn blocking on rule by rule. Before each release, replay recorded traffic through the new rules.

What would have been blocked?
$ npm run shieldtrail -- report events.jsonl
Which rules work, and which never fire?
$ npm run shieldtrail -- check events.jsonl
Would the new rules break real traffic? (exit code 1 = yes)
$ npm run shieldtrail -- replay events.jsonl
5

Write your own rules

Rules live in shieldtrail.policy.json, next to package.json: what to match, and whether to warn, block or ask a person. The first rule that matches wins; "defaults" adds the built-in rules. The panel's Watch / Block switches are saved in the same file.

shieldtrail.policy.json
{
  "mode": "shadow",
  "allowedDomains": ["api.acme.com"],
  "budget": { "maxCallsPerTool": 20, "maxCostUsd": 2 },
  "rules": [
    {
      "id": "no-external-forward",
      "description": "Inbox content forwarded outside the company",
      "match": {
        "kind": "tool_call",
        "target": "email.send",
        "args": { "to": "!*@acme.com" },
        "after": { "kind": "tool_call", "target": "email.inbox" }
      },
      "action": "block",
      "mode": "enforce"
    },
    {
      "id": "refund-needs-human",
      "match": { "kind": "tool_call", "target": "payments.refund" },
      "action": "ask"
    },
    "defaults"
  ]
}
  • Sequence rule: block mail forwarding outside the company, but only after the agent read the inbox.
  • ask: the step waits until someone approves it in the panel (or your Slack hook). No answer in time means blocked.
  • Budget: calls, time, tokens and money per task. Report model usage with trace.usage(response.usage).
  • Canaries, bound secrets and the kill switch stay in code: canaries: [createCanary()], secrets: [...], guard.halt().

Questions

Do I need an AI model or an API key?

No. Detection uses clear, deterministic rules. You can plug in an AI model if you want written incident summaries, but it is optional.

Does it send my data anywhere?

No. Events stay in your process, or in your own PostgreSQL. They only leave if you add an exporter (webhook, SIEM, OpenTelemetry). Secrets are masked before being stored.

What can it not see?

Inside trace.run() and trace.tool(), every fetch is checked, including those made by SDKs such as OpenAI or Stripe. Libraries that do not use fetch (axios in Node, raw sockets) and other programs are not seen: use a network proxy next to it.

Does the panel ship to production?

No. Its server starts only when NODE_ENV is development, listens on 127.0.0.1 and answers only pages from localhost. The script tag in your layout sits behind the same check.

Which apps can use it?

Any Node.js 20+ app: Express or Fastify servers, Next.js route handlers, workers, and apps that use MCP tools.
